# crawl-flow 项目说明

本文档描述 crawl-flow 当前已实现的行为，与仓库代码一一对应。定位：配置驱动的公开数据采集、解析、归一化与入库管道，自带离线 mock 站点。

### 入口与扩展点

- **程序入口**：`src/crawl_flow/cli.py`，通过 `pyproject.toml` 的 `console_scripts` 暴露为 `crawl-flow`。
- **核心执行入口**：`pipeline/run.py` 的 `run_source()`，CLI 只负责参数解析、配置加载与结果打印。
- **适配器扩展点**：实现 `sources/base.py` 的 `SourceAdapter` 子类，并在 `sources/__init__.py` 的 `ADAPTERS` 中注册；配置里的 `type` 需同时加入 `config.py` 的 `SourceType`。
- **抓取扩展点**：`fetch/client.py` 的 `Fetcher`，管道只依赖它的 `get()` 方法。
- **存储扩展点**：`storage/db.py` 的 `Database` 与 `storage/raw_store.py` 的 `RawStore`。
- **配置扩展点**：`config.py` 的 `SourceConfig` 与 `FieldMapping`，`extra="forbid"` 保证拼写错误的字段直接报错。

## 2. 功能说明

### F1 配置

- **输入**：`config/sources.yaml`（路径可用 `--config` 覆盖）。
- **处理**：`config.load_sources()` 读取 YAML，逐项用 `SourceConfig` 校验；校验通过后 `select_sources()` 按 `--source` / `--all` 选择源。
- **输出**：`list[SourceConfig]`，传给采集管道。
- **边界与失败**：
  - 文件不存在、YAML 语法错误、顶层缺少 `sources`、`sources` 为空、字段缺失或多余、`type` 不是 `api` / `html`、`base_url` 不是 http(s)、`detail_path` 缺少 `{id}`、`name` 重复 → 抛 `ConfigError`，CLI 打印「配置错误」并以**退出码 2** 结束。
  - `enabled: false` 的源会被 `--all` 跳过；显式 `--source` 仍可运行它（用于故障演练）。
  - `--source` 与 `--all` 同时出现、二者都未提供 → `ConfigError`，退出码 2。
  - `list_path` / `detail_path` 省略时按类型自动补默认值：api 为 `/api/items`、`/api/items/{id}`；html 为 `/list`、`/item/{id}`。

### F2 两个适配器

两个适配器都继承 `SourceAdapter`，统一提供：

| 方法 | 作用 |
| --- | --- |
| `iter_list_pages()` | 从第 1 页开始翻页，空页终止；列表页 4xx/5xx 抛 `FetchError` |
| `parse_list(result)` | 解析一页列表，返回 `ListItem(external_id, url)` 列表 |
| `parse_detail(result, external_id)` | 解析详情，返回源字段字典（键名供 `field_map` 使用） |
| `detail_url(external_id)` | 拼接详情 URL |

`demo_api`：

- 列表：`GET {base_url}/api/items?page=N&page_size=M`，响应 `{"total":…, "page":…, "page_size":…, "items":[…]}`。
- 详情：`GET {base_url}/api/items/{id}`，返回单条 JSON。
- 列表条目缺少 `id`、响应不是 JSON、详情不是对象、详情 `id` 与列表不一致、缺少 `title` → 抛 `ParseError`（带 `source`、`external_id`、`reason`）。

`demo_html`：

- 列表：`GET {base_url}/list?page=N`，解析 `table.items tbody tr`，从 `a[href]` 中用 `/item/{id}` 提取 `external_id`。
- 详情：`GET {base_url}/item/{id}`，按约定选择器解析：`h1.title`、`span.category`、`span.tags`、`span.date`、`div.content`。
- 缺少 `table.items`、某行缺少详情链接、链接中无法提取 id、缺少 `h1.title` 或 `div.content` → 抛 `ParseError`，不返回空结果。

### F3 采集主流程

- **输入**：CLI 参数（`--source` / `--all` / `--limit` / `--dry-run`）与选中的源配置。
- **处理**：`run_source()` 依次执行「列表翻页 → 详情抓取 → 解析 → 归一化 → 落 raw → 入库」。
- **输出**：`RunSummary(source, ok, failed, skipped, elapsed_ms)`；CLI 打印每个源的汇总与总计。
- **边界与失败**：
  - 列表页超时/连接失败/4xx/5xx → `FetchError`，**整轮中止**，CLI 退出码 2（已成功的源保留结果）。
  - 列表页内容无法解析 → `ParseError`，整轮中止，退出码 2。
  - 详情超时、4xx、5xx → 该条记 `failed`，继续下一条，整轮退出码仍为 0。
  - 详情解析失败或标题为空 → 该条记 `failed`，继续下一条。
  - 列表空页 → 翻页终止，正常结束；空源汇总为 `ok=0 failed=0 skipped=0`。
  - `--limit N`：每个源最多处理 N 条；为统计准确，后续列表页仍会翻页并枚举剩余条目，记为 `skipped`，不再抓详情。
  - `--dry-run`：完整执行抓取、解析、归一化与日志，但不写 raw 文件、不写数据库。
  - 同一轮内重复出现的 `external_id` 记为 `skipped`，避免重复请求。

### F4 存储

- **输入**：归一化后的 `Record` 与原始响应元信息 `RawRecord`。
- **处理**：
  - 原始响应按 `data/raw/{source}/{YYYY-MM-DD}/{external_id}.json` 落盘（日期取抓取时间 UTC）。
  - `raw_records` 与 `records` 均按 `(source, external_id)` 做 SQLite upsert。
- **输出**：
  - `records`：最新结构化记录；重复采集只更新字段与 `updated_at`，行数不增加。
  - `raw_records`：最新一次原始响应元信息（`ok` / `failed`），同样不增加行数。
- **边界与失败**：
  - 文件写入失败 → `StoreError`，CLI 退出码 2。
  - 数据库写入失败 → `StoreError`，CLI 退出码 2。
  - 失败详情同样落 raw 文件与 `raw_records`（`status=failed`），`raw_path` 指向故障响应快照。

### F5 错误处理

- **输入**：抓取、解析、存储过程中出现的异常。
- **处理**：按层使用 `FetchError` / `ParseError` / `StoreError`；管道只捕获单条详情可恢复的 `FetchError` 与 `ParseError`。
- **输出**：
  - 单条失败：`raw_records.status=failed`，`error` 为截断到 500 字符的错误摘要，日志输出 `status=failed`，汇总 `failed` 加一。
  - 整轮失败：列表页错误或存储错误向上抛出，CLI 打印原因并退出码 2。
- **边界**：不使用 `except Exception`；只有单条详情的抓取/解析错误被隔离。

### F6 日志

- **输入**：每条采集结果与每轮汇总。
- **处理**：`observability/logging.py` 配置标准库 `logging`，自定义 formatter 输出 `时间 level=… logger=…` 前缀。
- **输出**：
  - 每条固定一行：`source=… external_id=… status=ok|failed|skipped elapsed_ms=…`。
  - 每轮一行：`run summary source=… ok=… failed=… skipped=… elapsed_ms=… dry_run=…`。
  - 失败条目额外一行 WARNING，包含错误摘要。
- **边界**：默认 INFO；`--verbose` 打开 DEBUG（httpx 的请求日志仍保持 WARNING，避免淹没采集日志）。日志写 stderr，不污染 `db stats` 的表格输出。

### F7 CLI

| 命令 | 行为 |
| --- | --- |
| `crawl-flow run --source demo_api --limit 5` | 采集指定源前 5 条，打印汇总 |
| `crawl-flow run --all` | 采集所有 `enabled: true` 的源 |
| `crawl-flow run --source demo_api --dry-run` | 只解析，不落 raw 与数据库 |
| `crawl-flow run --all --scheduled` | 启用并发调度与限流采集（见 F9），多源共享同一调度池 |
| `crawl-flow run --source demo_api --scheduled --max-concurrency 4 --qps 10` | 覆盖全局并发与 QPS |
| `crawl-flow db stats` | 按源打印 records、raw 成功/失败数量与最近抓取时间 |
| `crawl-flow serve-mock --port 8010` | 启动本地 mock 站点 |

补充参数：`--config`（默认 `config/sources.yaml`）、`--scheduler-config`（默认
`config/scheduler.yaml`，仅 `--scheduled` 时读取）、`--scheduled/--no-scheduled`
（默认关闭，保持串行）、`--max-concurrency`、`--qps`、`--db`（默认
`data/crawl.db`）、`--raw-dir`（默认 `data/raw`）、`--verbose`。配置错误与整轮
失败退出码为 2；单条失败不影响退出码（0）；`db stats` 在数据库文件不存在时
退出码 1。

### F8 mock 站点

- **输入**：HTTP 请求（Flask 应用工厂 `mock_site/app.py:create_app`）。
- **处理**：从 `mock_site/fixtures/` 读取 API JSON 与 HTML 文件并按页返回。
- **输出与接口**：

| 接口 | 说明 |
| --- | --- |
| `GET /` | 索引页，列出示例链接 |
| `GET /api/items?page=N&page_size=M` | 分页 JSON：`{total, page, page_size, items}` |
| `GET /api/items/{id}` | 单条 JSON 详情 |
| `GET /list?page=N` | HTML 列表页（表格 + 详情链接） |
| `GET /item/{id}` | HTML 详情页 |

- **fixtures 规模**：API 3 页 × 5 条；HTML 3 页列表 + 15 个详情页，字段覆盖 id、标题、分类、标签、发布日期、正文，含中文与多种日期格式。
- **测试开关**：
  - `?fail=1`：详情返回 500；列表返回 503（用于验证整轮失败）。
  - `?empty=1`：列表返回空页，用于验证翻页终止。
  - 页码越界返回空页；未知 id 返回 404。
- **边界**：mock 站点只监听本地地址，不访问公网、不依赖外部服务。

### F9 请求调度与限流（可插拔模块）

默认串行行为不变；CLI 加 `--scheduled` 后，请求经 `scheduler/` 模块统一调度。
模块独立成包，适配器与 `pipeline/run.py` 的核心逻辑零修改——接入点只是把
`Fetcher` 换成同接口的 `ScheduledFetcher` 代理。单进程内完成，不引入任何
分布式依赖（无线程安全外部服务，全部基于标准库线程原语）。

#### F9.1 配置

调度配置位于 `config/scheduler.yaml`（`--scheduler-config` 可覆盖路径），
顶层为 `scheduler:` 映射；文件缺省时使用内置默认值。CLI 的
`--max-concurrency` / `--qps` 覆盖同名字段。

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `max_concurrency` | int | 8 | 全局在途请求总数硬上限（1–10000） |
| `qps` | float / null | null | 全局 QPS 上限，毫秒滑动窗口；null 不限 |
| `default_source_concurrency` | int | 2 | 源级并发缺省值 |
| `default_source_qps` | float / null | null | 源级 QPS 缺省值 |
| `sources[].name` | string | - | 源名，与 sources.yaml 对应 |
| `sources[].max_concurrency` | int / null | null | 单源并发覆盖，不得超过全局值 |
| `sources[].qps` | float / null | null | 单源 QPS 覆盖 |
| `sources[].weight` | int | 1 | 调度权重，决定加权配额比例 |
| `domain_rules[].domain` | string | - | 主机名（不含协议/端口/路径） |
| `domain_rules[].qps` | float | - | 该域名 QPS；小于 1 时自动放大窗口 |
| `domain_rules[].match` | exact/suffix | exact | suffix 同时覆盖子域，最长后缀优先 |

#### F9.2 调度模型

- **单调度线程 + 有界工作线程池**：一个 dispatcher 线程在同一把条件锁内完成
  选请求与发放全部限流令牌；`ThreadPoolExecutor` 工作线程只执行实际 HTTP 请求。
  调度状态无竞态计数，天然避免线程安全问题。
- **加权 DRR（亏空轮询）**：每源维护 `deficit`，轮询时按 `weight` 补充配额，
  长期看各源派发量之比等于权重之比；同分时轮转起点逐轮移动，避免固定源占便宜。
- **老化防饥饿**：队首请求等待超过阈值（默认 1000ms）的源被提到队首并保证
  至少获得一次调度尝试，低权重源不会长期拿不到配额（硬约束仍生效）。
- **两级并发**：全局与单源信号量在派发时同时判定，任一已满则请求留队，
  实际在途数不可能超过任一配置值。
- **多级限流**：全局 QPS、单源 QPS、域名 QPS 各持一个毫秒滑动窗口限流器，
  按「全局 → 单源 → 域名」顺序非阻塞申请，任一窗口满则请求留队等待，
  已申请的上游令牌逐档精确回滚（令牌式 release，跨线程不误删）。
- **毫秒精度**：所有时间戳取 `time.monotonic_ns()` 换算毫秒，不受系统时间
  回拨影响；窗口边界严格，QPS 误差 ≤5%。

#### F9.3 域名级限流

`DomainRateRegistry` 为每个生效域名持有独立限流器。`exact` 要求 host 完全
相等；`suffix` 命中 host 本身或其子域（`.` 边界，`notexample.com` 不会误匹配
`example.com`）；多规则命中时最长（最具体）域名胜出。命中规则且窗口已满时
请求**排队等待而非失败**，窗口滑出后由 dispatcher 自动重新派发。

#### F9.4 错误隔离与失败标记

单条请求的传输异常由工作线程捕获后原样回传给提交线程，`process_item` 的
`FetchError` / HTTP ≥400 / `ParseError` 处理路径与串行管道完全共用，失败条目
仍写 `raw_records(status=failed)` 与 raw 快照，汇总与退出码语义不变。

#### F9.5 自动降级

调度线程的未预期异常由兜底 `except` 捕获并调用 `enter_degradation()`：排队
请求全部立即标记 `SchedulerDegraded` 并唤醒提交者，`ScheduledFetcher` 捕获后
绕过调度池直接调用底层 `Fetcher` 串行执行。正在途请求不受影响，采集任务不
中断、不丢请求。降级/关闭路径对内部状态损坏做了防御，降级动作本身不会二次
抛异常。

#### F9.6 并发存储安全

`Database` 与 `RawStore` 各自带一把可重入锁；`ThreadSafeDatabase` /
`ThreadSafeRawStore` 代理复用底层实例的同一把锁（包装幂等），因此多源共享
存储时所有写入仍串行化，与单线程管道的写入顺序语义一致。

## 3. 数据模型

### records 表

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `id` | INTEGER | 主键、自增 | 行 ID |
| `source` | VARCHAR(128) | 非空 | 源名称，对应配置 `name` |
| `external_id` | VARCHAR(256) | 非空 | 源内唯一 ID |
| `title` | VARCHAR(512) | 非空 | 清洗后的标题 |
| `category` | VARCHAR(128) | 可空 | 分类，空字符串归一为 NULL |
| `tags` | JSON | 非空 | 标签数组，SQLite 中以 JSON 文本存储 |
| `published_at` | DATETIME | 可空 | 归一化后的发布时间 |
| `content` | TEXT | 非空 | 去 HTML 标签后的纯文本，保留段落换行 |
| `url` | VARCHAR(2048) | 非空 | 详情 URL（或 `field_map.url` 指定的源字段） |
| `fetched_at` | DATETIME | 非空 | 本次抓取时间（UTC） |
| `updated_at` | DATETIME | 非空 | 最近一次 upsert 时间（UTC） |

- 唯一键：`(source, external_id)`。
- 索引：唯一键索引；`(source, category)` 复合索引。

### raw_records 表

| 字段 | 类型 | 约束 | 含义 |
| --- | --- | --- | --- |
| `id` | INTEGER | 主键、自增 | 行 ID |
| `source` | VARCHAR(128) | 非空 | 源名称 |
| `external_id` | VARCHAR(256) | 非空 | 源内唯一 ID |
| `url` | VARCHAR(2048) | 非空 | 实际请求的详情 URL |
| `http_status` | INTEGER | 可空 | HTTP 状态码；传输异常时为 NULL |
| `fetched_at` | DATETIME | 非空 | 抓取时间（UTC） |
| `status` | VARCHAR(16) | 非空 | `ok` 或 `failed` |
| `error` | TEXT | 可空 | 错误摘要（最长 500 字符） |
| `raw_path` | VARCHAR(1024) | 可空 | 原始响应文件路径 |

- 唯一键：`(source, external_id)`，同一源同一记录只保留最新一次采集元信息。
- 索引：唯一键索引；`status` 单列索引。

### raw 文件规则

- 目录：`data/raw/{source}/{YYYY-MM-DD}/`，日期取 `fetched_at` 的 UTC 日期。
- 文件名：`{external_id}.json`；非 `[A-Za-z0-9._-]` 字符替换为 `_`，长度截断到 120。
- 成功响应 JSON 字段：`source`、`external_id`、`url`、`status`、`fetched_at`、`headers`、`body`。
- 失败响应额外含 `error`；传输异常时 `status` 为 `null`、`body` 为空串。
- 写入采用「临时文件 + 原子替换」，重复采集覆盖同名文件。

## 4. 关键流程

一次 `crawl-flow run --source demo_api --limit 5` 的完整路径：

1. **CLI 解析参数**：`cli.py:run_command` 读取 `--source/--all/--limit/--dry-run/--config/--db/--raw-dir`，初始化日志（`observability/logging.py`）。
2. **加载配置**：`config.py:load_sources` 读取并校验 `sources.yaml`，`select_sources` 选出目标源；失败则退出码 2。
3. **初始化资源**：`storage/db.py:Database.init` 建表；`storage/raw_store.py:RawStore` 记录 raw 根目录；`fetch/client.py:Fetcher` 建立 HTTP 客户端。
4. **创建适配器**：`sources/__init__.py:create_adapter` 按 `type` 实例化 `DemoApiAdapter` 或 `DemoHtmlAdapter`。
5. **列表翻页**：`sources/base.py:iter_list_pages` 请求第 1..N 页；状态码 ≥400 抛 `FetchError`；`parse_list` 产出 `ListItem`；空页终止。
6. **详情抓取**：`pipeline/run.py:process_item` 调用 `adapter.fetch_detail`；传输异常或状态码 ≥400 转失败分支。
7. **解析与归一化**：`adapter.parse_detail` 得到源字段字典；`pipeline/normalize.py:normalize_record` 清洗空白、HTML、标签、日期并做字段映射，生成 `Record`；解析错误转失败分支。
8. **原始响应落盘**：`raw_store.save` 写入 `data/raw/{source}/{日期}/{id}.json`；`Database.upsert_raw` 写入 `raw_records`。
9. **幂等入库**：`Database.upsert_record` 按 `(source, external_id)` upsert `records`；随后输出单条日志 `source=… external_id=… status=… elapsed_ms=…`。
10. **汇总**：`run_source` 输出 `run summary` 日志并返回 `RunSummary`；`cli.py` 打印「本轮汇总」与总计，正常退出码 0。

失败分支：详情失败走 `_fail`，同样落 raw 与 `raw_records`（`status=failed`），日志 `status=failed`，不中断后续条目；列表页失败则直接向上抛，CLI 退出码 2。

## 5. 配置说明

`sources.yaml` 顶层是 `sources` 列表，每个源字段如下：

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `name` | string | 是 | 无 | 源名称，唯一，只允许字母、数字、`_`、`-` |
| `type` | `api` / `html` | 是 | 无 | 适配器类型 |
| `base_url` | string | 是 | 无 | 站点根地址，必须 `http://` 或 `https://`，末尾斜杠会被去掉 |
| `enabled` | bool | 否 | `true` | `--all` 是否运行该源 |
| `page_size` | int | 否 | `5` | 每页条数，范围 1–100；仅 `api` 类型使用 |
| `timeout_seconds` | float | 否 | `10` | 单请求超时，范围 0–120 |
| `list_path` | string | 否 | api `/api/items`；html `/list` | 列表路径，可自带查询串（如 `?fail=1`） |
| `detail_path` | string | 否 | api `/api/items/{id}`；html `/item/{id}` | 详情路径，必须包含 `{id}` |
| `field_map.title` | string | 否 | `title` | 标题对应的源字段名 |
| `field_map.category` | string | 否 | `category` | 分类对应的源字段名 |
| `field_map.tags` | string | 否 | `tags` | 标签对应的源字段名，值可为数组或分隔字符串 |
| `field_map.published_at` | string | 否 | `published_at` | 发布日期对应的源字段名 |
| `field_map.content` | string | 否 | `content` | 正文对应的源字段名，可含 HTML |
| `field_map.url` | string / null | 否 | `null` | 若指定，从该源字段取标准 URL；否则用详情请求 URL |

完整示例：

```yaml
sources:
  - name: demo_api
    type: api
    base_url: http://127.0.0.1:8010
    enabled: true
    page_size: 5
    timeout_seconds: 10
    list_path: /api/items
    detail_path: /api/items/{id}
    field_map:
      title: title
      category: category
      tags: tags
      published_at: published_at
      content: content
      url: null

  - name: demo_html
    type: html
    base_url: http://127.0.0.1:8010
    enabled: true
    page_size: 5
    list_path: /list
    detail_path: /item/{id}
    field_map:
      title: title
      category: category
      tags: tags
      published_at: published_at
      content: content
      url: null

  - name: demo_api_flaky
    type: api
    base_url: http://127.0.0.1:8010
    enabled: false
    detail_path: /api/items/{id}?fail=1
```

注意：

- 配置模型 `extra="forbid"`，未知字段会直接校验失败。
- `base_url` 不含尾斜杠；适配器自行拼接路径。
- 仓库自带的 `demo_api_flaky`（详情 500）与 `demo_api_broken`（列表 503）默认 `enabled: false`，用于演示错误处理。

## 6. 已知限制

以下能力在 README 与本文档中一致声明为**不实现**：

1. **增量游标 / 断点续采**：每次采集都从列表第 1 页全量重扫，没有游标、时间窗口或断点续采。
2. **代理池 / 分布式调度**：`--scheduled` 已支持单进程内的并发、全局/单源
   QPS、域名级限流与加权调度（见 F9），但不提供代理 IP 池，也不支持多机
   分布式任务分发；调度状态只存在于当前进程。
3. **内容指纹去重**：只做 `(source, external_id)` 唯一约束，不计算正文哈希，不做跨源/跨 ID 去重。
4. **重试退避策略、死信队列、失败重放**：只对连接级传输异常做一次立即重试；5xx 不重试；失败记录只留档，没有死信队列与自动重放。
5. **清洗规则 DSL、字段质量校验**：清洗规则固定写在 `pipeline/normalize.py`，不可配置；日期无法解析时 `published_at` 记为 NULL，不做字段质量评分或告警。
6. **任务编排 / 定时调度 / 指标暴露**：仅支持手动 CLI 执行，无调度器、无 Prometheus 等指标端点。
7. **浏览器渲染（Playwright）**：仅抓取静态 HTTP 响应，不执行 JavaScript，动态渲染页面不在覆盖范围。

当前实现的额外边界：

- 为让 `skipped` 统计准确，达到 `--limit` 后仍会翻完剩余列表页（不抓详情），大列表源会产生额外列表请求。
- `raw_records` 每个 `(source, external_id)` 只保留最新一次记录，不保留历史版本。
- `published_at` 的时区偏移在 SQLite `DATETIME` 中不保留，读回为无时区 `datetime`。
- 翻页有 500 页上限保护，超过会抛 `FetchError` 并终止整轮。
- HTML 适配器依赖固定选择器，目标站点结构变化时需要修改或新增适配器。
